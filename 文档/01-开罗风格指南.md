## 1. 画面构成（相机 / 网格 / 分层）

1. **视角**：等距斜俯视，俯角约 30–45°（目测估计），**无透视灭点**；房间后墙画在画面上缘，家具与角色按屏幕菱形网格对齐。
   - 见 `参考帧/视频抽帧/GDS_trailer_00m16s_办公室_斜视四人桌面.png`（视频 00:16，干净办公室无弹窗）、`参考帧/官方截图/GameDevStory_steam_04.jpg`。
2. **房间单元**：一个封闭矩形房间承担整屏主体，约占画面宽 88–92%、高 78–85%（目测估计）；天花板不画；右侧或右侧中段留出「门/走廊/电梯」开口作为画外空间提示（`GDS_trailer_00m02s_办公室_火灾事件全屏.png`，00:02）。
3. **网格**：地板为菱形（旋转 45° 方格）棋盘贴图，格对角约 2 个原生像素单元宽；**角色与家具各占整数格**，桌椅成组为 2 格×1 格。
4. **分层顺序**：地板 → 地毯/阴影 → 家具与设备 → 角色 → 遮挡前景（桌子前沿遮住角色下半身、绿植挡住墙角）→ UI 层。角色被家具部分遮挡是开罗画面的关键识别点，出图时不要把所有小人都画完整。
5. **构图留白**（目测估计）：顶部状态条、底部属性条、右下按钮组各占约 5–8% 高度；中央 60%×50% 区域留给弹窗。
6. **出图规格建议**：1920×1080 或 3840×2160，且**像素格必须整数倍**（见 §3）。参考视频里单帧内同时存在整间办公室与 3~6 组家具，可供「成立办公室」与「开发/发布会」不同场面复用同一空间。

## 3. 像素密度、描边与阴影

- **实测像素格距**：1080p 视频中场景像素块约 **4 px**（对 `GDS_trailer_00m16s_办公室_斜视四人桌面.png` 的家具/地板区域做水平/垂直差自相关，主周期 4、次周期 9；对角台阶放大 10× 计数亦为 5±1 px，含压缩带来的 1 px 溢边）。
  → **推断（未证实）**：若按 4 px/格反推，PC 版原始渲染画布约为 **480×270**。**下述缩放基准只对这个推断画布成立**，不是通用铁律。
  **整数缩放建议（以 480×270 为基准时）**：1080p＝4×、2160p＝8× 是整数倍；**720p 对该基准是非整数（2.67×），会出现半格**。若本 PV 成品需要 720p 或其它尺寸，应先自定一个便于整除的基准画布（例如 640×360，2× 放大到 1280×720），**不要直接沿用 480×270 这个推断值，也不要把 720p 一律排除**。
- **描边**：所有像素素材用 **1 原生像素（1080p 下 4 px）深色描边**（`#463d3e`–`#262967` 一类），描边色随物体明度微调，不是纯黑。
- **阴影**：短投影直接画在右下方向，纯色块，**无渐变、无柔化**（见 `GDS_trailer_00m16s_办公室_斜视四人桌面.png` 桌椅下方）。
- **同一画面内的两种精度**：场景/图标是像素素材，而 **UI 文字是高分辨率抗锯齿文字**（1080p 下笔画约 2–3 px，边缘平滑；放大验证见 `参考帧/接触表/GDS_弹窗字体_3x放大.png`）。复刻时不要把所有素材统一成同一像素格：**「像素场景 + 高清字体」正是开罗现代移植版的混合特征**。
- 小图标（如升级徽标 `Lv1`）与场景共用同一像素格（1080p 下笔画块约 4–5 px），即图标不是额外放大版。

## 4. UI 与字体（可执行骨架）

**弹窗标准骨架**（以 `GDS_trailer_00m11s_招聘_HireNewEmployees弹窗.png` 00:11 为准）：
1. 外框：浅色底（`#f8f7fd`–`#fefeff`）＋ 1 原生像素冷灰描边（`#a0a3a9`）＋ 右下 1–2 原生像素投影；
2. 标题带：页面顶部的浅青灰条，左对齐标题（如 `Hire New Employees 1/1`）；
3. 内容区：分栏或分节，节与节之间用 1 px 淡紫蓝分隔线（`#d6eaea`）；
4. 底部：右侧按钮（`Hire` / `OK` / `Finish`），按钮为浅色圆角矩形＋描边；
5. 弹窗宽约占屏 40–60%（目测估计），高按内容行数增长，垂直居中；同类弹窗出现位置固定，便于做「连播」剪辑。

**状态条**（每帧都在）：
- 顶栏：左「日历 Y1 M12 W4」＋右「资金 $9,059.3K」，数字带 `$` 与 `K` 后缀，右对齐（`参考帧/官方截图/GameDevStory_steam_00.jpg`；`GDS_trailer_00m05s_办公室_DevelopGames横幅.png`）。

## 5. 演出节奏（实测）

**镜头切换（GDS，`scdet` 阈值取 5 时）**：在该阈值下检出 10 处变化幅度较大的位置——
`13.08s, 15.05s, 21.25s, 22.82s, 25.19s, 26.43s, 33.33s, 35.04s, 37.44s, 46.98s`，其中 46.98s 分数最高（22.7，进片尾标题卡）。
→ 该结果只能说明「在这个阈值下这些位置画面变化明显」，**不能推出全片只有 10 次切换，也不能推出开罗 PV 都不硬切**（阈值、样本、编码噪声都会影响检出）。
→ 就本样本的观感：所取的 GDS 片段偏重**同一机位的缓慢平移/推近 + 弹窗逐层出现/消失 + 数值跳动**，硬切极少。**建议本 PV 沿用这种「少硬切、多弹窗替换」的编排**，但按创作需要该切就切。

**节拍规律（基于本样本的创作建议，不是硬规则）**：
- 样本里一个弹窗大体就是一拍，**每拍约 2–4 s**，本样本全片约 12–14 拍；
- 样本中多数拍呈「弹窗出现 → 数值变化 → 确认（OK/Hire/Finish）」三段式，**建议本 PV 沿用**；
- 建议同一机位连续不超过 1–2 拍，之后换弹窗或换房间（本样本的实际分布与之一致）；
- 四支样本的结尾都是「全员像素小人并排列队 + LOGO」（GDS 00:48、DV2 01:02、SM 01:02、HSS 00:48），**建议作为收尾模板**。

**通用建议（无音频依据，仅按开罗惯例给出的可执行默认）**：
- 用 chiptune/8-bit 音色（方波主旋律 + 简单鼓组），2–4 小节循环，与 2–4 s 的弹窗节拍对齐（每拍给一次音乐重音）；

- 「爆发/核爆」段用低通噪声 + 低频下坠，随后切回循环主题；
- 混音目标**参考**（注：**四支样本并不一致**，DV2 仅 −36.4 LUFS 明显例外；这**不是任何发布平台的响度标准**，成片请以目标平台规范为准）；响的那三支集成响度约 −21 ~ −24 LUFS，真峰留约 6 dB 余量。
